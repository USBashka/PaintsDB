---
name: paintsdb-recipes
description: Переносить рецепты красок с фотографий и записей в открытое приложение PaintsDB через его MCP, сопоставлять компоненты и проверять расчёт. Использовать для работы с PaintsDB, а не для общего распознавания изображений.
---

Работай через инструменты PaintsDB. Фотографии распознаются на стороне ИИ и не передаются приложению. Не записывай данные непосредственно в SQLite.

1. Вызови `paints_status`, проверь открытый файл и сохрани `context`. Передавай context во все операции с базой. При `database_changed` прочитай состояние заново и выясни, соответствует ли новый файл задаче; не повторяй подготовленную запись в другой базе автоматически.
2. Прочитай обозначения и исходные массы с изображения. Не выдумывай неразборчивые символы. Все реквизиты рецепта необязательны; неизвестные название, код цвета, марку, автомобиль, заказ-наряд и комментарий можно оставить пустыми. Если дата неизвестна, приложение использует текущую дату; для старой фотографии уточни дату, если от неё зависит исходная стоимость.
3. Найди компоненты через `paints_list_components` по коду или алиасу. Код — строка: сохраняй ведущие нули. Неоднозначный алиас требует выбора. Не заменяй неизвестный компонент похожим. Новый компонент создавай только в пределах поручения пользователя.
4. Передавай `lines` как список `{component_id, mass_expression}`. Сохраняй исходное выражение целиком: `20+15+кап`, а не только `36`. `кап` всегда равна 1 г. Поддержаны числа с точкой, +, -, *, / и скобки.
5. Проверь через `paints_calculate` с месяцем изготовления. Цена упаковки делится на произведение объёма в литрах и массы литра в граммах. Вес крышки не вычитается. Предыдущая цена переносится вперёд; будущая назад не переносится. `total=null` означает неполные данные.
6. Сохрани через `paints_save_recipe`. Успешные изменения применяются сразу; отдельное подтверждение колориста в PaintsDB не требуется. Проверь ID, массы, месяцы цен и сумму. Для редактирования сначала получи актуальные `id` и `revision`; при конфликте не затирай чужое изменение.

Одинаковый код цвета допускает несколько независимых рецептов. `paints_compare_recipes` приводит варианты к 1000 г и одному месяцу. Исправление цены не меняет исходный снимок; изменение состава или даты рецепта пересоздаёт его. Предыдущие редакции рецепта не хранятся.

Excel: сначала `paints_preview_import`, затем `paints_apply_import` с явно выбранными ключами строк. Проверяй errors, warnings и повторы кода. Строка без полного прайса может создать только компонент. Выбирай одну из конфликтующих строк лишь при наличии основания. Импорт выбранного набора атомарен.

Результаты имеют структуру `{ok:true,data:...}`. Ошибки MCP содержат code, message и при возможности field. Резервирование, открытие базы, удаление и экспорт используй в рамках поручения. Токен подключения не включай в отчёты и репозиторий.
